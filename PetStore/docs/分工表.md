## 六、优先级约定（用户裁定，全员遵守）

## 七、AI 协作机制说明（供报告"体会/方法"章节引用）

本项目由 **AI Agent 工作组**完成，协作机制有明文章程（`_crew/公约.md` **v1.3**）。可概括为：

1. **文件即合同**：跨成员指令一律写进目标成员「当前任务」区，编号 `T-YYYYMMDD-NN` 全局唯一。
2. **权限矩阵**：成员只写自己文件夹 + `_crew/裁决请求/`；`项目/` 由 dev 按任务卡范围写、rel 按提交范围写；助手**不碰代码**。
3. **请示而不擅决**：遇越界或歧义只能写 `ASK-*.md` 停下等批复。
4. **接口契约**（v1.1 起，§13）：跨成员技术接口须落成 `项目/docs/接口契约.md`，**必须写类型**；消费方直读，助手不转述。
5. **取证式汇报**（v1.1 起，§14）：凡"已删除/已创建/测试通过/返回 200"等断言须附可复现核验方式；助手的结论同样受审计，成员据实反驳不构成违规。
6. **能力申报**（v1.2 起，§16）：启动必报四项能力；缺口须上报；**视觉验证默认兜底人＝用户**。
7. **反并行冲突**（v1.2 起，§17）：写前声明 / 写后结束，撞车时能定位归因。
8. **独立门禁**：提交前由 rel-01 自己跑测试，不引用 dev 自述。
9. **防虚报**：未实现功能不得做成可用假象（购物车、验证码均按此处理）。
10. **文件编辑纪律**（v1.3 起，§18）：结构编辑超 2 次须整篇重写，且编辑后校验标题序列。
